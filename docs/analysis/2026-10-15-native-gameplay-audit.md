# Аудит активной игровой основы — 15.10.2026

Проверены чтением все 35 Java-файлов `common/src/main/java`, `fabric/src/main/java`, `neoforge/src/main/java`, существовавшие на начале аудита. Это проверка активной основы перед следующей unit; параллельные новые реализации других агентов в её охват не входят. `git status --short` перед работой был чистым. Основная спецификация — приватный oracle TC4 4.2.3.5 в `../work/thaumcraft-4.2.3.5-oracle`; OpenTC4 `80aac29c52543ef51766c4b0788fba782abb3b0b` и Architectury `1509b3192910aaca0af8bba1b55d189a675010bf` использовались только как закреплённые references. Decompiled code в репозиторий не добавлялся.

## Подтверждённые ошибки

1. **P2 — сканирование узла начисляло полный текущий vis вместо исследовательской награды. Исправлено, запуск проверок ожидается.** `common/src/main/java/thaumcraft/common/items/relics/ItemThaumometer.java:81` передавал `node.getAspects()` непосредственно в награды. Oracle `thaumcraft/common/lib/research/ScanManager.java:235–247` сначала строит отдельный список: аспекты в sorted order, для каждого `max(4, amount / 10)` с целочисленным делением. Обычный узел с 25 vis давал 25 очков вместо 4, с 50 vis — 50 вместо 5. Новый `ScanManager.nodeScanAspects` (`common/.../ScanManager.java:36–49`) восстанавливает исходное правило только для node path. Это устранение drift, не отклонение от TC4. Native node остаётся обычным: bonus aspects типов PURE/DARK/HUNGRY/TAINTED/UNSTABLE пока pending.

2. **P2 — block scan использовал registry id блока вместо соответствующего предмета. Исправлено, запуск проверок ожидается.** Прежние `common/src/main/java/thaumcraft/common/items/relics/ItemThaumometer.java:84–85` искали binding по `BuiltInRegistries.BLOCK`; oracle `thaumcraft/common/items/relics/ItemThaumometer.java:108–122` использует `getPickBlock` и затем item id/metadata. Конкретный случай: лежащий `minecraft:redstone` имеет прямой binding `potentia=3` (`common/src/main/resources/data/thaumcraft/tc4/object_aspects.json:1843–1856`), но поставленная пыль определялась как `minecraft:redstone_wire` и получала пустой список. Новый код `ItemThaumometer.java:84–91` вызывает mapped 1.21.1 `Block.getCloneItemStack(LevelReader, BlockPos, BlockState)` на сервере и использует ITEM registry id полученного stack; пустой результат отвергается. Это устранение drift выбора цели, отдельно от отсутствующего recipe-derived tagging.

## Границы основы, не ошибки завершённых units

- `ScanManager` пока не создаёт research clues/item/entity/aspect triggers; `ItemThaumometer` выбирает только лежащие предметы и блоки/узлы, без живых существ. Эти функции прямо отсутствуют и требуют следующего переноса.
- `ObjectAspectCatalog` намеренно ограничен безусловными прямыми tags; recipe-derived, complex/component-dependent tags и runtime addon registration отсутствуют. Не следует объявлять весь object tagging готовым по одному каталогу.
- `ResearchCatalog`/`ResearchDefinition` содержат данные, а не полный `ResearchManager`. Research notes/table, siblings completion, warp за исследования и получение знаний через gameplay ещё не приняты как готовые units.
- Банка реализует 64 единицы одного аспекта, обмен фиалами по 8 и сохранение в block item; label/filter, пустое sneaking-очищение, comparator, void/brain/node jars и транспорт essentia отсутствуют. Существующая проверка drop manually загружает payload в tile; реальный `BlockItem.place` с сохранённой эссенцией ещё не проверен.
- `TileNode` — creative test node с primal aspects, без ecology/регенерации/worldgen/type/modifier. `ItemWandCasting` — только wood/iron storage/drain; полные wand interactions/foci/assembly отсутствуют. Текущая арифметика centivis/partial-unit rounding соответствует oracle `ItemWandCasting.java:340–349`, `TileNode.java:398–423`.

## Authority, сохранение и fidelity

В просмотренных активных путях не найден подтверждённый C2S exploit или потеря сохранённых знаний: scan target выбирает сервер; session начинается в серверном `use`; завершение проверяет target/timing; phial exchange изменяет jar/held item только на сервере; knowledge packet зарегистрирован S2C; mixin сохраняет player-owned state, а clone копирует его перед respawn sync. Это статический вывод, не доказательство adversarial multiplayer или полного save/chunk-unload сценария. Свободный public API вызов из другого server mod не является самостоятельной сетевой уязвимостью.

Clone picking сохраняет нативный stack/item mapping для slabs, wall/standing variants и state-aware overrides; это не добавляет отсутствующие aspect bindings. Block states одного предмета намеренно разделяют scan id по item id. Нестандартные component-dependent stacks, специальные addon pick hooks с hit/player arguments и полная прежняя metadata/grouped-tags таблица остаются pending; объявлять их паритет по этой замене нельзя. Дополнительная source extraction или loader-only API для этого исправления не требовалась.

Отдельно следует принять/отклонить уже существующие изменения геометрических quirks перед переносом research minigame. `HexUtils.java:56–58` использует случайный начальный угол ring distribution, тогда как oracle `thaumcraft/common/lib/utils/HexUtils.java:52–62` потребляет RNG, но начинает с нулевого угла; `HexUtils.java:95–97` намеренно исправляет исходное преобразование axial→cubic. Текущих native gameplay callsites этих методов не найдено, поэтому это пока fidelity risk, не действующий gameplay regression. Original round-trip defect описан в комментарии; случайный угол требует отдельного решения и записи deviation либо сохранения quirk.

Охват включал shared bootstrap/registries, обе loader bootstraps, клиентский bootstrap, aspects API и hex utility, все native item/block/tile classes, knowledge mixin/access/lifecycle/payload, object/research catalogs, commands и runtime-test support. Нет оснований считать этот аудит проверкой 934 legacy classes или подтверждением полного TC4 parity.
