# Голодный сундук — следующая группа Fabric

## Реализация

Интегрированы блок/предмет/BE, 27-слотовый стандартный GUI, сохранение полных
компонентов предметов, доступ обычных воронок и компаратор. Подбор только при
физическом контакте: сначала объединение совпадающих стопок, затем пустые слоты;
остаток остаётся в том же ItemEntity. При удалении содержимое передаётся уже
существующей очереди отложенного выброса. Тикер не ищет и не притягивает предметы.

Используются исходная текстура и кубическое открытие крышки; предмет рисуется
через зарегистрированный BER. Рецепт: семь досок, дубовый люк,
Aer5/Ordo3/Perditio3, исследование HUNGRYCHEST. Книга использует реальный рецепт
и явный alias исходной иконки. В исследованиях сохранены Fames3/Vacuos3, без
родительского требования. Прямые аспекты сундуку не придуманы: работает обычное
выведение из рецепта; исходная complex-добавка Motus1 для дубового люка включена.

Root после передачи runtime уточнил две границы: физический контакт использует
корпус высотой15/16 (включая лежащий сверху предмет, численный допуск1e-7), а не
весь блок; ориентация игроком использует исходный piston-height/yaw алгоритм,
а не ближайшее направление взгляда. Для старого posY+1.82-yOffset используется
современная координата ног+1.82. Повороты0/1 сохраняются без наклона модели.

## Проверка и границы

Оригинал и точные особенности: [source review](2026-10-18-hungry-chest-original.md).
Передачи авторов: [runtime](2026-10-18-hungry-chest-runtime-notes.md),
[client](2026-10-18-hungry-chest-client-notes.md). Их хеши runtime относятся к
состоянию до указанных двух root-коррекций, не к текущим файлам.

Целевая сборка Fabric **PASS38s** (`.tmp/hungry-chest-build1.log`): main-исходники,
production remap и изоляция тестов. Шесть существующих aspect-data JUnit PASS.
Private development JAR10861935bytes/SHA256
`fe5dbcbecbe1bf70fb659650b361a52ba19ce82dfb9f910895f4c873120e3ea4`.
Игровой запуск/GUI/воронки/save-reload/визуализация пока
**не проверены**, длинный smoke не запускается. Это не закрытие всех големов.
Предварительный экспорт бура остаётся отдельным JAR и не заменяется этим build.
Работа продолжается над первым соломенным големом; игровой PASS сундука не выдуман.

Оговорённые адаптации: native item maximum для пустых слотов вместо допуска
аномального overstack; нет потери остатка. Используется существующая безопасная
очередь выброса вместо точного старого визуального дробления на10–30 предметов;
никакой cross-file power-loss атомарности не обещано. Старые миры не мигрируются.
