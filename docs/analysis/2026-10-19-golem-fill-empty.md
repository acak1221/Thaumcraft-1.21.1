## Coordinates, timing and inventory rules

- Walking home **H₀** and clicked face **F** identify attached inventory **B = H₀ − F**. Placement offsets from clicked block, records H₀, then `setup(side)`; constructor face0=DOWN only before setup, not an UP/default marker face (`ItemGolemPlacer.java:164–176,195–226`; `E:149,386–389`). Markers identify **block position + dimension + clicked inventory face**; no markers means no remote targets, not an adjacent-inventory scan. Bell never rehomes.
- Ordinary range16 (`E:460–473`): inventory Goto selects nearest eligible block center with **golem-to-target d² ≤256**, excluding B; home restriction separately uses **home-to-block d² <256**. Working at markers requires **d² <4**; home take/place/replace/drop requires idle navigation and **home-center d² ≤5**. Return-home starts at d²≥3 (`H:54–85`; `AIFillGoto:91–115`; `AIEmptyGoto:57–80`; `O/common/entities/ai/misc/AIReturnHome.java:40–56`). These constants are squared distances, not four/five-block reaches.
- Home take/place/replace and both Goto scans check `ticks % golemDelay == 0`; default **5 ticks**, minimum1. Marker take/place/drop and home-drop are not all independently five-tick-gated. Goto lasts up to200 updates while navigating, with a20-update unsticking attempt; successful container interactions hold for5 chest-animation updates. Failed Empty destinations suppress that item for **10000 milliseconds** by default, minimum1000—not a permanent blacklist (`Config.java:425–435,879–880`; `AIFillGoto:120–144`; `AIEmptyGoto:95–119`; `H:515–578`). A native tick cooldown would be an explicit timing adaptation.
- Original `ISidedInventory` uses slots exposed on **F/marker.side**, extraction permission, insertion permission and slot validity; ordinary `IInventory` uses all slots. Extraction returns **min(request, stock in the first matching extractable slot)**, not an assembled multi-slot batch. Insertion probes copies and commits only accepted quantities, returning leftovers; double-chest partners are included (`O/common/lib/utils/InventoryUtils.java:49–158,208–266,458–473`; `H:54–75,122–164`).
- Native first scope: reuse Gather's supported vanilla/Hungry `Container` / `WorldlyContainer` and native double-chest resolution; obey `getSlotsForFace`, `canTakeItemThroughFace`, `canPlaceItemThroughFace`, `canPlaceItem`, item/slot limits. Exact item + components (including damage), **ignoring count**, maps default non-fuzzy matching (`InventoryUtils:313–340`; `E:834–843`). Unknown/unloaded/unsupported inventories never authorize extraction/payment or become implicit drop targets. No provider/automation framework is needed.

## Fill0: marked sources → attached home

1. Priority chain: HomeReplace0, HomePlace1, HomeDrop2, FillTake3, FillGoto4; shared ReturnHome6 (`E:269–275,346–350`). Six filter rows without upgrades; **at least one exemplar is mandatory** (`E:198–231`; `AIFillGoto:52–59`).
2. Default toggle0=false = **Precise amount**. Count matching items already in B's face-visible slots, including chest partner; compare against desired ghost quantities. With a distinct filter row, deficit = wanted−present; satisfied rows do not fetch. Counting examines exposed slots, not whether those existing items are extractable. Toggle0=true = **Any amount** bypasses home stock counting but still uses exemplars (`H:166–223`; `O/client/gui/GuiGolem.java:190–202`).
3. With empty cargo, choose the first missing exemplar having marked supply, then its nearest in-range source. After navigation ends, FillTake checks adjacent marked containers/sides and extracts **min(deficit, carry space)**, or carry space in Any mode. It need not take from a stored exclusive destination; adjacent eligible markers are re-read. Return home, insert actual cargo, retain remainder (`AIFillGoto:52–115`; `AIFillTake:38–74`; `AIHomePlace:35–62,85–118`). No home-space reservation is performed before fetching.
4. Full/side-denied home gives **no insertion progress and retains cargo**. Original missing/non-inventory home is different: **AIHomeDrop intentionally throws real cargo toward B**, pickup delay10; it is not a full-chest overflow rule (`AIHomeDrop:37–47,71–88`). Native equivalent must require a known loaded non-container target and successful item-entity admission before clearing cargo; otherwise retain it.

## Empty1: attached home → marked destinations

1. Priority chain: HomeReplace0, EmptyPlace1, EmptyDrop2, EmptyGoto3, **HomeTake4** (the oracle's home-pickup class is `AIHomeTake`, not `AIHomePickup`), ReturnHome6 (`E:278–283,346–350`).
2. Empty filters = any exact item; populated filters = whitelist, **not desired retained home quantities**. Before withdrawing, require a destination with some room for that candidate, or a deliberate non-inventory drop marker; failed candidates enter the item timeout. HomeTake then extracts up to material carry space, **ignoring ghost quantity**, from B through F. This preflight is not a full-batch reservation (`H:448–479,515–543,581–655`; `AIHomeTake:37–105`).
3. Carry to nearest eligible marked inventory in range; when navigation ends and a marked container is adjacent, insert through its marked faces, preserving leftovers. With no eligible target remaining or a timed-out item, HomeReplace tries returning cargo to B; if B cannot accept it, **keep cargo** (`AIEmptyGoto:49–80`; `AIEmptyPlace:41–76,100–139`; `AIHomeReplace:37–69,92–125`). Progress means actual extracted/inserted/admitted count, not a path or room probe.
4. Original non-inventory markers are deliberate throw destinations (`AIEmptyDrop:30–43,58–78`), not Use/place-block actions. That Goto fallback is list-order and lacks the inventory branch's range guard (`AIEmptyGoto:82–90`); drop adjacency still requires d²<4. If a first container-only implementation omits world throws, record that concrete missing branch rather than claim full Empty parity. Unknown inventory support must never trigger it.

## Ghost quantities are not cargo; concrete original quirks

- `InventoryMob` saves the ghost inventory; `getAmountNeededSmart` sums matching configured quantities; **real cargo is separate `itemCarried`**, separately saved (`O/common/entities/InventoryMob.java:145–164,236–276`; `E:142–145,601–623`). Carry limits Straw/Wood/Tallow/Clay/Stone/Iron/Thaumium = **1/4/8/8/16/32/32**, independent of wanted stock (`EnumGolemType.java:10–17`; `E:355–361,793–797`).
- **Fill double-slot quirk:** `ContainerGolem.java:46–58` adds both an unrestricted `SlotGhost` (limit256) **and** a limit1 ghost for each same underlying row at the same coordinates: twelve menu entries, still only six logical filters. Empty adds only limit1 ghosts (`O/common/container/SlotGhost.java:17–33`). Do not interpret doubled menu entries as doubled inventory/cargo.
- Ghost clicks copy, never pay/return stock; empty-hand left −1/right +1; shift-left clears, shift-right +16 clamped to the clicked slot limit (`ContainerGhostSlots.java:44–59,71–101,112–133`). **Shift bug hazard:** `ContainerGolem:114–130` defines a real-stack merge quick-move using logical slotCount as menu boundary, wrong for doubled Fill entries and unsafe for ghosts. The overriding click handler intercepts ordinary shift mode; this helper is not evidence every shift duplicates stock. Native quickMoveStack must not merge ghosts into real inventories.
- Additional quantity defect: `H:188–220` compares present stock with the summed duplicate-row target but emits **individual row count−present**, which can be nonpositive. Duplicate-row arithmetic needs an explicit native decision, not an invented claim that original Fill always maintains the summed target exactly.
