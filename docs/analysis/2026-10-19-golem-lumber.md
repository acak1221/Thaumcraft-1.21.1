## Scan, approach and work timer

- Constructor computes **r=ceil(getRange()/3)** (A:56–63); ordinary range16 gives **r6**, not a16-block log scan. Every `golemDelay` ticks (default5), only with delay<0 and navigation idle, try **4r random positions** using the golem RNG. Baseline: **24 attempts**, X/Z in home±6, Y in home±3; first recognized log wins, not nearest-tree search or Harvest's crop-column checklist (A:66–79,154–174; E:460–473; `Config.java:879`). General Y uses the source's float-half-radius/int-cast formula; upgraded odd radii are not a symmetric integer cube.
- After finding a log, descend its column **only while the next lower log is closer to the golem**, rather than always finding the soil/root. Snapshot anchor block+metadata, navigate to its center, lifetime200 continuation checks; continue only while that exact anchor state remains (A:82–89,142–169). At **feet-to-anchor-center distance²≤4**, advance work; outside reach the timer does not advance.
- Strength = material strength + Earth-upgrade count (E:850–851); ordinary Straw/Wood/Tallow/Clay/Stone/Iron/Thaumium strengths **0/1/2/2/3/4/4** (`EnumGolemType.java:10–17`). Timer uses **anchor hardness**, not a player axe speed:

```text
delay = (int) max(5.0F, (20.0F - strength*3.0F) * hardness)
mod   = delay / round(delay / 6.0F)       // integer quotient
```

A:90–110 decrements delay once per in-reach update; intermediate action/sound/crack stages occur on mod boundaries when navigation is idle. At zero, harvest **one selected log**, reset/re-path while anchor survives; otherwise find the first adjacent log in X/Z/Y −1…1 order, within r of home on each axis (A:115–144). Harvest refreshes count200; reset clears cracking with stage−1. This is neither instant whole-tree destruction nor one chop every200 ticks.

## What “chop the tree” actually means

- U:202–211 recognizes non-air blocks that **canSustainLeaves**, or an exact entry in the elemental-axe log list. **No actual leaves, natural-generation provenance or soil are required**: placed log structures and isolated logs qualify. `BlockMagicalLog.java:138–147` explicitly supports leaves/wood.
- Each A:147–151 call uses **B.breakFurthestBlock**, whose search is a **greedy outward walk**, not flood-fill/global furthest search: initialize at anchor with distance0; at each point scan X −2…2, Y **+2 down to−2**, Z −2…2; follow the first same-**Block identity**, recognized log, hardness≥0, with strictly greater squared distance from anchor, then recurse (B:169–209). Metadata/axis need not match. It can jump gaps/diagonals within2 and cross nearby trees of the same block class.
- Nominal anchor-relative bounds are **|ΔX|≤24, |ΔY|≤48, |ΔZ|≤24**; encountering an out-of-bounds candidate returns from that scan immediately, an original traversal quirk. Only the final selected endpoint is harvested per timer. Repeated outward pruning can remove trunks/branches progressively, but **not every arbitrary disconnected/branched crown is guaranteed**. Remote endpoints can lie outside the small home scan/proximity radius; permission at the anchor alone is insufficient.
- **Leaves are not directly chopped.** On reported success B:210–219 marks blocks and schedules the endpoint's7×7×7 neighborhood for **150…299-tick** updates. Log removal triggers normal leaf decay (`BlockMagicalLog:89–103`); leaf support/persistent flags determine what actually decays. Preserve normal leaf drops rather than vacuuming/deleting the canopy. Original magical decay sapling chances are **Greatwood1/200, Silverwood1/250**, for decaying nonpersistent leaves (`BlockMagicalLeaves.java:144–200,219–230,264–265`), not guaranteed saplings or a generic vanilla rate.
- B:66–97,155–166 checks nonnegative hardness, harvestability, removal callbacks and successful removal before block harvesting. The fresh fake player is **empty-handed: default Fortune0/no Silk Touch**; A never equips the infusion axe or charges its durability. Unlike the player's elemental axe path, Lumber passes followItem=false, so drops remain at the actual endpoint (`ItemElementalAxe.java:146–155`). Native must preserve real per-block loot/count/components; do not synthesize one anchor-log stack for a tree or pay from candidate snapshots.
