## Native entry and the real Fabric BEFORE hook

- Cached public signature: **`InteractionResult ServerPlayerGameMode.useItemOn(ServerPlayer player, Level level, ItemStack stack, InteractionHand hand, BlockHitResult hit)`**. Use the borrowed actor's own `gameMode`, same ServerLevel, MAIN_HAND and the **actual hand reference**; never a preview copy. `UseOnContext(Player,InteractionHand,BlockHitResult)` independently fetches that actor's hand, so argument/hand identity matters.
- `BlockHitResult(Vec3,Direction,BlockPos,boolean)` is public. Retain selected marker+face identity; original block-mode hit is **clicked T center** (`Vec3.atCenterOf(T)`), selected face, inside=false, not an implicit face-center hit. Set actor to **worker XYZ/yaw/pitch**, not target XYZ; preserve the independent real-worker reach/eyes/obstruction checks.
- Fabric **`net.fabricmc.fabric.mixin.event.interaction.ServerPlayerInteractionManagerMixin`**, enabled in `fabric-events-interaction-v0.mixins.json`, injects **`@Inject(at=@At("HEAD"),method="interactBlock",cancellable=true)`** (Yarn name; Mojang `useItemOn`). It calls **`UseBlockCallback.EVENT.invoker().interact(player,world,hand,blockHitResult)`**. Every result other than PASS cancels/returns; PASS alone reaches the native body. Thus a **direct gameMode call dispatches the event once**, not only a packet-handler call. **Do not also invoke the event manually.** No break-event substitute or effectful UseBlock query for Harvest/other systems.
- A PASS listener can change target, hand, options or permissions. Fresh checking merely before/after the whole method is insufficient. Minimal proposed integration: a **Use-lease-only cancellable mixin fence immediately before the first native `Level.getBlockState(BlockPos)` invocation inside useItemOn**, after Fabric's HEAD callback, revalidating live worker/job, captured target/state/face, affected cell, actor/stock, options and permissions; deny the native body if stale. Exact invocation target: **`Lnet/minecraft/world/level/Level;getBlockState(Lnet/minecraft/core/BlockPos;)Lnet/minecraft/world/level/block/state/BlockState;`**, ordinal0, BEFORE. Do not rely on another HEAD injector's ordering, register a purported “last” callback, recursively reenter useItemOn or dispatch another event. Non-PASS/throw still requires stock settlement.
- Native order after the hook: block feature/game-mode checks → `BlockState.useItemOn` → MAIN_HAND/default `useWithoutItem` when requested → nonempty/off-cooldown `ItemStack.useOn`. The internal stack copy is a **criterion snapshot**, not extra spendable stock. Direct calls do **not** reproduce all packet-handler validation or its ANY_BLOCK_USE criterion/swing/update packets.

## Finite native effects, not synthesized placement

- Empty-hand vanilla lever/button goes through native `useWithoutItem`: lever toggles, writes state/notifies neighbors/sound/game events; button presses and schedules its native release tick. Do not call `pull`/`press` directly, imitate redstone state changes, or admit arbitrary block subclasses/GUI-opening blocks. With a home inventory, empty supplied stock is **not** permission to switch to bare hand.
- Cached Items.WHEAT_SEEDS is **ItemNameBlockItem(Blocks.WHEAT)**. Actual `ItemStack.useOn(UseOnContext)` → BlockItem.useOn → `place(BlockPlaceContext)` selects the air **above** nonreplaceable farmland for UP, checks placement/survival/collision, writes wheat, runs placement/criterion/sound/game-event work, then **`actualStack.consume(1,player)`**. Survival/no-infinite-materials is essential; useItemOn's creative branch restores the old count. Do not set wheat yourself, decrement a ghost, refill the hand, make a bucket/output or award XP.
- Admit only explicitly supported seed components; **refuse unknown/action-changing payloads without scrubbing**. In particular native **FOOD** makes BlockItem.useOn fall back to Item.use after failed placement (held eating), while **BLOCK_STATE** can alter the placed crop; BE/entity/container payloads are not seed privileges. Preserve every component of any real remainder even when it is no longer eligible for another action.
- Ordinary hooks/neighbor ticks can propagate beyond the selected block. Placement notifications/criteria/game events occur **before final seed consumption**, and lever writes precede later feedback; exceptions can therefore leave a changed world with a still-present hand. PASS/FAIL/throw is not a rollback signal. **Never replay this click, restore old counts/world state, infer refunds or fabricate consumption to “repair” native exceptions.** This finite route is not universal addon/fatal-error atomicity or authorization to run world actions during this consultation.
