# Магическая лампа и янтарь — контракт TC4, 20.10.2026

Источник — TC4 4.2.3.5, CFR вне репозитория: `TileArcaneLamp`, `BlockMetalDevice`
(metadata 7), `BlockMetalDeviceItem`, `BlockAiry` (metadata 3), `TileArcaneBore:364–390`,
`BlockCosmeticOpaque`, `ConfigRecipes:210,447–450`, `ConfigResearch:218`.

## Исходное поведение

- Лампа — металлическое устройство, твёрдость 3, исходное сопротивление 17
  (хранится ×3, отдаётся /5; нативное 10,2), свет 15; тело x/z 4..12, y 2..14 в шестнадцатых блока.
- `facing` смотрит на опору: размещение на стороне клика сохраняет противоположное направление.
  Соседское изменение удаляет лампу с обычным дропом, если опора стала **воздухом**;
  непрозрачная полная грань не требуется. У неё нет редстоун-паузы или оплаты vis.
- Раз за серверный тик берутся шесть `nextInt(16)` строго x,x,y,y,z,z. Каждая разность
  даёт смещение −15..15 с треугольным распределением. Y ограничивается сверху высотой
  колонки +4, снизу 5. В воздушную клетку, которая ещё не является `blockAiry`, при
  суммарном освещении <9 ставится `blockAiry:3` со светом 15.
- `blockAiry:3` — невидимый, заменяемый воздух, без коллизии, предмета или block entity.
  `TileArcaneLampLight` лежит в оригинальном JAR, но не создаётся этим metadata и не
  регистрируется: нельзя незаметно добавить его периодическое истечение к живой механике.
- При удалении лампы весь свет `blockAiry:3` в кубе ±15 удаляется, в том числе свет
  соседней лампы. В исходных световых клетках нет владельца/координат источника.
- После успешного рытья Бур ищет первую лампу по четырём горизонтальным соседям базы
  (N,S,W,E). Один `nextInt(32)` задаёт чётную дальность 0..62 и исходную чередующуюся
  позицию в тоннеле. Если там воздух, не `blockAiry` и свет <15, ставится тот же свет.
  Проверяется только первая найденная лампа. Далёкий тоннельный свет вне куба удаления
  не исчезает вместе с лампой — исходная особенность, а не работа неиспользуемой плитки.
- Рецепт `ArcaneLamp`, исследование `ARCANELAMP`: ` S /IAI/ N `, S — датчик дневного
  света, I — железо, A — янтарный блок, N — нитор; `ignis 8, aer 8, aqua 4, perditio 4`.
- Янтарь — четыре `amber_gem` квадратом в один блок; четыре блока квадратом дают четыре
  янтарных кирпича; один блок распускается в четыре самоцвета. Оба блока имеют твёрдость
  1,5, сопротивление 3 после пересчёта, звук камня, прозрачные грани и непрозрачность 3.

## Адаптация 1.21.1

Лампа и свет имеют отдельные id `arcane_lamp` / `arcane_light`; невидимый свет не имеет
инвентарного предмета. Направление сохранено в block state, дополнительно записывается
исходный `orientation` для аудита. `ArcaneLampRules`, `TileArcaneLamp` и
`ArcaneLampLighting` реализуют освещение; `BlockAmber` сохраняет opacity 3.

С разрешения ведущего адаптирована нижняя граница миров: `minBuildHeight + 5`, то есть
при старом minY=0 остаётся 5, а в новых шахтах minY=−64 — −59. Абсолютное значение 5
в отрицательных шахтах создавало бы свет на десятки блоков выше лампы, вне её куба уборки.
Верхняя граница берётся из нативного `WORLD_SURFACE`; генерация не загружает отсутствующие
чанки. Куб удаления сохраняет исходный локальный обход, а тоннельный helper работает только
в уже загруженной области. Рендер тела использует оригинальные анимированные текстуры;
`TileArcaneLampRenderer` рисует исходное сопло/крепление через существующую модель базы
Бура с шестью оригинальными поворотами. Изображение в клиенте ещё не проверено.
