# Loot bags, original weighted pools and native dungeon availability

Authority: TC4 4.2.3.5 `Config.initLoot`515–601, `Utils.generateLoot/genGear/getGearItemForSlot`380–end, `ItemLootBag`; vanilla1.7.10 `PotionHelper` and `EntityItem` constructors. The private oracle and untouched vanilla JAR remain outside the repository. No original decompile is included here.

Implemented: three flattened common/uncommon/rare bag items, original stack limit16 and rarity/tooltip/icons; original mutable public `WeightedRandomLoot` lists/API; original default pool entry counts85/90/92 and total weights2943/2813/2591. Coin entries remain counts1/2/3 with weights2500/2250/2000; rare-only pearl and nether star each weight1. The old `by` item is the experience bottle, not a saddle. One time-seeded process template supplies all charged lesser-vis amulets. The root-owned Fabric adapter appends TC additions once to each native chest's primary weighted pool, competing with its existing entries; Pech receives the original38 uniform dungeon-entry descriptors.

`generateLoot` preserves short-circuit RNG order: common skips the gear float, uncommon/rare chance `.025F*rarity`; quality is `nextInt(2)` plus FIVE independent float checks `.2/.15/.1/.095/.095`, then slot5, damage bounded by `1+maxDamage/6`, and the original nextInt4 enchant gate. The literal slot0 quality sequence is iron axe, iron sword, golden axe, golden sword, thaumium sword, diamond sword, void sword. Armor uses leather/gold/chain/iron/thaumium/diamond/void. Old Forge/vanilla enchantment rules are supplied by the separate `OriginalLootEnchantments` adapter. BOOK conversion mutates the shared public template across all tier aliases; subsequent selection copies the cached enchanted book without new enchantment RNG. Native dynamic enchantment holders are rebound to the current registry by exact key/level, preserving tooltip visibility and public pools across server lifetimes.

Potion adapter: the exact Config bit loop yields72 distinct weighted metadata entries, weight144 per tier, including duplicate-effect strong/extended variants. All72 metadata/weight/effect/duration/amplifier/color tuples were compared to an executed untouched vanilla1.7.10 PotionHelper oracle. Original splash durations include its rounding (+1, e.g. regeneration676/338/1801 and speed2701/1351/7201). Native items use `PotionContents` CUSTOM effects and explicit original color, with no built-in base potion holder: combining a modern base holder with the custom effect would silently apply both effects and often retain the longer incorrect duration. Names use native translated potion names. This finite loot adaptation does **not** implement the entire old vanilla brewing engine; conversion of these custom-only legacy potions in a vanilla brewing stand and global legacy potion attribute/formula parity remain pending.

Original physical opening: `8+world.random.nextInt(5)` independent output rolls, at the actual player's FEET position, original EntityItem float-widened horizontal scatter ±`.1F` and vertical `.2F`; scatter uses Math.random independently of the world's loot RNG. The actual native connected actor/hand/reference/count/components and original position are witnessed after planning and loading the real existing SavedData owner. The actual bag shrinks once before each staged result enters `DeferredItemDrops.enqueueDirected`. The private opening frame rejects synchronous recursive use during planning/publication; canceled physical ADD is retried from durable custody, with no bag refund/re-roll. Ordinary native creative use keeps its bag via ServerPlayerGameMode's original count-restoring wrapper. Sound remains coins volume.75/pitch1.

Validation: all72 potion fact tuples passed a standalone Java comparison against the untouched executed vanilla oracle; this is data evidence, not a Gradle/GameTest pass. Added JUnit checks cover loop cardinality/weight, literal duration/amplifier/color vectors and float scatter. Added native GameTest checks cover exact pool totals, all potion component codec round trips, seven gear quality branches, weighted boundaries/no extra RNG, BOOK alias mutation/cache, registry holders, naturally loaded native dungeon availability/Pech descriptors, real survival payment and literal seed0 result (8 rolls,7 single coins+1 gold ingot), canceled ADD/recursive flush/save-load/exact resumed item trajectory, ordinary POST retry, and real creative wrapper seed3 maximum12 rolls with bag preservation. Integrated build and GameTest evidence must be recorded only after the root run.

Native renderer inspection, multiplayer survival acquisition, and NeoForge parity are unverified. No claim of complete vanilla brewing compatibility is made.
