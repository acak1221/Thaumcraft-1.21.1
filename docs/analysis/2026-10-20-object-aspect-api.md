## Native behavior

`ThaumcraftApi.objectTags` and `groupedObjectTags` expose mutable concurrent maps with original-shaped item/metadata list keys. The native resolver reads these maps. Completed-registry catalogue validation seeds bundled direct defaults once with `putIfAbsent`; later public replacements, removals and clears are not silently restored from the immutable extraction catalogue. The catalogue's direct-ID inspection methods remain provenance views, rather than another runtime override layer.

Direct overloads accept actual `ItemStack`, `Item + explicit metadata` or `ResourceLocation + explicit metadata`. Stack registration ignores count, custom name and other components as original NBT was ignored. Native damage is the stack metadata; flattened old subtype identities require their actual native registry IDs. Native `TagKey<Item>` and namespaced String item-tag overloads snapshot current bound members immediately. No general Forge OreDictionary registry or heuristic old-name translation is invented; callers map old ore names to actual native tags explicitly.

`ObjectAspectRegistry` holds the independent original lookup/complex policies. `ObjectAspectResolver.baseTags(stack, level, metadata)` is the explicit metadata adapter. Native `ItemStack.getDamageValue` and `setDamageValue` clamp to `[0,maxDamage]`, including0 on ordinary items (confirmed with native javap). Therefore a32767 registration/query or group `[7,0]` must not be represented by fabricated out-of-range damage or an invented max-durability component. Explicit metadata overloads and `ItemWitness(stackCopy, metadata)` preserve those values separately. No old-world item ID/metadata import is implemented.

The physical thaumometer and native callbacks use `scanTags`, which applies the current live group's first metadata value once. Dissolution and ordinary `get` use the real native stack metadata. Physical stack count, components and damage are not changed by scan canonicalization. Type1 physical sessions use the canonical metadata; callback type1 session identity follows its returned native witness, while type2 drops retain their entity-ID session and actual item clue witness. Aspect resolution uses the canonical metadata independently.

Raw range-array keys preserve their early return and bypass cap64/dynamic base bonuses. Resolver returns remain independent copies so a scan/recipe consumer cannot mutate the caller's public registration. Public map mutations are observable on the next lookup; no resolved aspect cache conceals them.

## Native lifecycle and reload adaptations

Modern recipes belong to a loaded server data/recipe manager. The explicit `registerComplexObjectTag(stack, additions, serverLevel)` and `Item + explicit metadata + additions + level` overloads perform immediate original branch behavior on the server thread. The original-shaped two-argument overload works only while a valid server recipe context is available; otherwise it throws a clear `IllegalStateException` explaining that mod-init registration must move to the server recipe lifecycle or use the Level overload. There is **no deferred registration queue**, so public map mutation order remains concrete and reviewable.

Root wires `ObjectAspectRegistry.serverStarted(server)` and `.serverStopped(server)`. Only a weak server reference is held; neither a Level nor RecipeManager is retained by this context. Explicit Level access also checks the owning server thread. Shutdown clears the context.

Existing bundled complex registrations and the anchored bookshelf/salis/crucible expressions remain calculated on demand. This preserves the already-tested native `RecipeManager.replaceRecipes` invalidation behavior, including the piston test that removes/restores its actual recipe. Their declared metadata is visible to `ThaumcraftApi.exists`, so registering complex additions over an already-defined native complex item follows the original **existing** branch. A caller's explicit complex registration materializes its own immediate snapshot as original API registration did. This is an explicit native reload adapter, not a claim that the original process-global recipe cache has been ported unchanged.

The Goggles resource's former `original_metadata:0` provenance typo is corrected to the actual wildcard declaration. The historical ALL90 snapshot test normalizes only that one old metadata value for its old digest after separately asserting the corrected live value; all other old fields remain pinned. Arcane Ear row434 is separately asserted against its original registration and actual native identity. No unrelated late item is substituted or registered speculatively.
