# Original loot enchantment selection

OriginalLootEnchantments.enchant(ServerLevel,ItemStack,RandomSource,int) replaces modern random enchanting only for original loot callers. Source: unmodified official1.7.10 client SHA1e80d9b3bf5085002218d4be59e668bac718abbc6, actual afv212–288/aft/individual enchantment methods; TC4 EnchantmentHaste/Repair and Config275–279. Forge1.7.10 patch pinned9274e4fe435cb415099a8216c1b42235f185443e changes candidate testing to canApplyAtEnchantingTable OR plain-book/isAllowedOnBooks and compatibility to both-direction vetoes. Decompiled originals, SHA-verified Mojang libraries and executable probe outputs remain outside this repository.

The adapter owns24 original vanilla ids0..7/16..21/32..35/48..51/61..62 plus TC4 defaults Haste150 and Repair151. No modern mending/curses/new enchantments, native supported-item tags, min/max costs or weights choose candidates. Exact original enchantability boost uses two bounded integer draws, two FLOAT draws, original0.15 spread/rounding, highest eligible rank per id, HashMap<Integer,Pick> and old weighted selection. Additional choices use original nextInt(50) and halving loop; removal preserves original compatibility including Feather Falling/protection, damage family, all three Silk/loot vetoes and Repair/Unbreaking.

Integer HashMap keys are the original numeric ids inserted in original registry-array order. JVM HashMap ordering was never specified across historical Java6/7/8 implementations; the supported native runtime is Java21, and no cross-JVM bitwise claim is made. The unmodified official helper was executed under the same JDK21 with actual original vanilla BOOK/items. Fifteen book5/15/30 seed vectors and the next RNG value after each selection are recorded in a meaningful native JUnit test. The shared pure selection engine verifies all fifteen unchanged official vectors using the original unpatched one-way compatibility policy. Production always uses Forge's bilateral policy. A meaningful separate vector proves why the policies differ even when a forbidden pair would not be selected: book30/seed1 selects protectionIII/SilkI/FlameI in vanilla; removing Luck61 from the post-Silk candidate WEIGHTS yields protectionIII/SilkI/LureII under Forge, with the same next RNG value136569. TC4 bounds and both-direction vetoes are separately asserted. Modern RandomSource supplies the draws; LegacyRandomSource seeded vectors match java.util.Random, while the caller's native world RNG remains authoritative.

Forge override behavior is retained: damage enchants can apply to axes; thorns to all armor; efficiency/silk can recognize shears though their original zero enchantability prevents random table selection; native hoes are explicitly excluded from original ItemTool classification. Vanilla hoes retain original enchantability0; TC4 native hoe overrides return5. Haste applies only to boots/actual Hover Harness; Repair requires an actual damageable IRepairable item. Plain books admit every original allowed-on-books entry, including Repair despite ItemBook itself not being damageable. Unbreaking's override falls back to ITEM breakability even for Unbreakable stack NBT; Repair remains blocked by that flag. Modern item categories/enchantability for newly introduced vanilla/addon items are forced APIs without an original acquisition claim.

Original helper changes plain BOOK to ENCHANTED_BOOK even with no selected enchantments. Native immutable item identity requires transmuteCopy, preserving count/components, so callers MUST retain the returned template. Ordinary equipment is mutated. Registry holders are resolved only after selection, by original stable keys in the current server registry. The adapter keeps no static holders or item templates. Mutable loot pools must rebind their stored enchanted-book data across server lifetimes; pool ownership belongs to LootTables. Native enchantment components have unique holder keys, so arbitrary repeated calls cannot retain duplicate same-id legacy NBT list entries; bounded original callers use fresh gear and once-converted plain-book templates.

Main source and JUnit/doc are coherent and await root compile/run. No native loot-bag runtime or client visual acceptance is claimed here; those caller scenarios belong to the adjacent loot unit.

First root compile passed main;682JUnit had one owned test failure because an unpatched vanilla oracle vector was incorrectly compared against Forge bilateral candidate weights. The shared-engine policy distinction above preserves every executed oracle vector and production Forge behavior; corrected tests await rerun.
