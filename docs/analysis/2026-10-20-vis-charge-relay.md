# Vis Charge Relay — контракт TC4, 20.10.2026

Источник — TC4 4.2.3.5, CFR вне репозитория: `TileMagicWorkbenchCharger`,
`TileVisRelay`, `BlockMetalDevice` metadata2, `TileMagicWorkbenchChargerRenderer`,
`ConfigRecipes.NodeChargeRelay` и исследование `VISCHARGERELAY`.

## Исходное поведение

Зарядное реле — участник VisNet радиусом8, не источник. После обычного серверного
тика графа оно ищет настоящий магический верстак непосредственно снизу и его
физический wand slot10. Для каждого первичного аспекта, которому есть место,
запрашивает `min(5, capacity-current)` сырых CV и добавляет только фактический grant.
Это пять сотых vis за тик для каждого аспекта, не пять целых vis. Без верстака,
палочки или свободного места реле не оплачивает зарядку, но остаётся узлом графа.

Ориентация всегда0/DOWN; тело занимает x/z5..11,y8..16 в шестнадцатых блока.
Правило удаления при потере опоры у исходного metadata14 не распространяется на
metadata2. Исходный динамический свет10/2 также относится только к14; зарядное
реле само не светит. Сохраняются исходные металлические hardness3/resistance10,2,
звук и обычный предмет при добыче правильным инструментом.

Осколок меняет attunement; повтор того же или balanced сбрасывает его в−1.
Щелчок палочкой циклически меняет−1..5. Ни осколок, ни vis палочки не расходуются.
Исходный рецепт `NodeChargeRelay`, `VISCHARGERELAY`: ` R /W W/I I`, R — vis relay,
W — greatwood wand rod, I — железо; `ignis16, ordo16, aer16`.

Рендер использует оригинальный `vis_relay.obj`: RingFloat, четыре Support,
Crystal, фиксированные исходные повороты и цвет attunement. Яркость кристалла —
`(linked?50:0)+150*(sin(ticks/2)*0,05+0,95)`. Родительский луч следует существующей
нативной адаптации VisNet; его затухание зависит от игровых тиков, не FPS.

## Адаптация 1.21.1 и оплата

Отдельный id — `vis_charge_relay`; блок/плитка/предмет регистрируются через
`ThaumcraftVisCharging`. Отдельный подкласс `TileVisNode` повторяет политику реле,
поскольку нативный обычный `TileVisRelay` финальный. Неверное сохранённое значение
attunement сохраняется как `RejectedVisChargeRelay` и выключает узел; transient
charge/pulse не восстанавливается как новый запас.

В исходном Java-коде кредит в палочку выполнялся после `consumeVis`, который уже
вызывал эффекты промежуточных узлов. Синхронное удаление верстака из такого эффекта
копировало ещё пустую палочку в дроп, а последующий кредит доставался отсоединённому
объекту. Это воспроизводимая потеря уже оплаченного ресурса в современной системе
callback. С разрешения ведущего добавлен закрытый нативный переход в `VisNetHandler`:

1. Зарядное реле до оплаты захватывает реальный верстак, block state, точную ссылку
   slot10 и исходный immutable `WandData`, заранее готовит пять возможных кредитов.
2. Исполнитель проверяет тот же серверный узел/верстак/slot/component после проверки
   маршрута непосредственно перед дебетом источника.
3. После фактического дебета и перед любыми pulse callback заменяет компонент
   захваченной палочки на заранее подготовленный результат точного grant.
4. Публичный вход кредита требует точного приватного ThreadLocal frame исполнителя;
   его нельзя вызвать вне оплаченной фазы или повторить. Это закрытый `instanceof`
   нативного устройства, без общего пользовательского callback API.

Обычные positional drain через зарядное реле и явный `consumeVis` вне фазы зарядки
сохраняют прежнюю семантику; они не дают дополнительный кредит палочке. Для источников
сохраняется существующий callback-free контракт: произвольный addon, нарушающий его,
не становится транзакционным благодаря этой адаптации.

## Проверка

**Implemented:** gameplay, оригинальные рецепт/mesh, клиентская регистрация;
общие bootstrap, книга/локализация и Fabric item-render route подключает ведущий.
**Built / game-tested / seen:** pending.

`VisChargeRelayRuntimeChecks` использует реальное преобразование объявленного raw
node за1001 обновление и настоящий renewable source. Проверяются все шесть аспектов,
лимит5, остаток3 в той же8-CV эпохе, хвост ёмкости2, неверный слот/предмет, обычная
ретрансляция, настройка и native save/load. Регрессионный callback удаляет настоящий
верстак из первого промежуточного pulse: единственная физически эвакуированная
палочка должна содержать оплаченные aer5 при остатке источника3, без продолжения
других аспектов. Требуется повтор предыдущих focused VisNet runtime checks.

Клиентские картинка/лучи/звук, несколько игроков и NeoForge этой записью не подтверждены.
