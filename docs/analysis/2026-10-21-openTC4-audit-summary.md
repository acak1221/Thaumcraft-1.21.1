# Сверка порта с читаемым исходником 1.7.10 (OpenTC4) — 21.10.2026

## Что это

Девять параллельных субагентов сверили порт TC4 4.2.3.5 на 1.21.1 с **читаемым** исходником
1.7.10, а не с SRG-именами оракула:

- `/home/Acak/work/opentc4` — OpenTC4 на коммите `80aac29c52543ef51766c4b0788fba782abb3b0b`,
  тот же 1.7.10-код TC4, но с читаемыми именами ваниллы;
- `/home/Acak/work/thaumcraft-4.2.3.5-oracle` — оракул (авторитет);
- `/home/Acak/work/mc1710-src` — читаемая ванилла 1.7.10, найденная агентом по големам;
- `scripts/porting/resolve_srg.py` — постоянный инструмент: SRG-имя → читаемое имя ваниллы
  по карте MCP 1.7.10 (`mcp_stable-12-1.7.10`).

Правило приоритета: **оракул — истина**, OpenTC4 и читаемая ванилла 1.7.10 — источник имён и
поведения ваниллы, а 1.12-справочник этого репозитория — пример, не спецификация.

## Почему это было нужно

Аудит 21.10.2026 (1043 из 1044 единиц ledger) читал оракул по SRG-именам. Там, где SRG-имя
одноимённо в 1.7.10 и в 1.12, но означает разные вещи, чтение давало ложный вывод. Доказанные
на этой волне расхождения карт:

| SRG-имя 1.7.10 | Значение в 1.7.10 | Что читалось по 1.12-справочнику |
|---|---|---|
| `DamageSource.field_76367_g` | **cactus** | `IN_WALL` (стена) |
| `DamageSource.field_76376_m` | **magic** | `INDIRECT_MAGIC` |
| `Entity.field_71088_bW` | `timeUntilPortal` | `pickupDelay` |
| `Block.setResistance(x)` | хранит `x*3`, геттер `/5` → **эффективно 0.6·x** | сырое `x` |

Именно эти четыре расхождения породили ложные дефекты в предыдущем аудите и реальные дефекты
в порту.

## Доказанная семантика 1.7.10 (проверена байткодом)

- `Block.setResistance(x)` → `blockResistance = x * 3.0F`; `getExplosionResistance(Entity)` →
  `blockResistance / 5.0F` → **эффективное сопротивление = 0.6·x**. В 1.21.1
  `Properties.strength(hardness, resistance)` не умножает и не делит, значит в порт кладётся
  эффективное значение. Абсолютные значения из собственных геттеров оригинала (999, 30, 100,
  50, 200) не масштабируются.
- `EntityMob.isValidLightLevel` (1.7.10 `net/minecraft/entity/monster/EntityMob.java:140-146`):
  **сохранённый** небесный свет против `nextInt(32)`, затем свет блока против `nextInt(8)`.
  Портал использовал максимальную сырую яркость, из-за чего в открытом поле днём мобы не
  появлялись вообще.
- `EntityFireBat` (1.7.10): `func_70814_o` (isValidLightLevel) возвращает **true** — ограничения
  света нет.
- `EntityWisp` (1.7.10 `EntityWisp.java:310-320`): затемнённый небесный свет против
  `nextInt(32)`, затем свет блока против `nextInt(8)`.
- `EntityAI` выполняет цели **в порядке регистрации**; общие цели голема в порту стояли перед
  целями ядра.
- `EntityGolemBase:1131-1138` и `EntityTravelingTrunk:106-109`: `field_76367_g` = **cactus**,
  `field_76376_m` = **magic**.
