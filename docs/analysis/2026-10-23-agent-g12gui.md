## Candidate and experiment

Magic Box's menu uses native `Container.stillValidBlockEntity` instead of the
backend's `stillValid`, bypassing its rejected-data gate. Its ordinary Slots
also accept writes that `TileMagicBox.setItem` refuses while data is rejected.
The native empty-slot transfer removes items from the source before the
backend setter is called: ignoring the setter is not rejection-safe.

`GuiRejectionRuntimeChecks.magicBox` uses the existing connected-survival Actor,
opens the registered block's real menu through `gameMode.useItemOn`, and checks
seven actual dirt move in and out normally. It then explicitly loads malformed
NBT into the **same** live block entity and shift-clicks seven dirt. The test
counts dirt in player inventory, backend, cursor, and nearby item entities.
This is a fault-state fixture, **not** evidence of a survival player being able
to corrupt NBT or a remote item-duplication exploit. Expected count: seven.

Original behavior reference: readable OpenTC4 `ContainerMagicBox:58-59`
delegates `canInteractWith` to the box. Original unrestricted healthy inputs
remain accepted. The private original-JAR oracle was not accessed; no new
original-gameplay parity assertion is made.

## Fix

`ContainerMagicBox` now consults the backend's `stillValid` **before** using the
native BE helper, delegates slot placement to backend `canPlaceItem`, refuses
pickup for an invalid viewer/backend, and gates ordinary clicks through the
same active-session check as shift-click. It does not change healthy accepted
items, 27-slot layout, linked-box routing, or inventory close ownership.

The post-fix invocation used the exact command above against a deleted/fresh
world: **PASS**, all 1 required tests passed, `BUILD SUCCESSFUL in 2m 18s`.
`.tmp-g12-after.log:429,455` is the local evidence log;
`fabric/build/gametest-focused-results.xml` contains the passing testcase.
The final source compiled and ran on a real headless Fabric GameTest server.
Healthy transfer succeeds, rejected transfer retains seven dirt, and validity,
placement and pickup predicates all agree with the backend's rejection.
`git diff --check` also passed. The private Gradle home is ignored in `.gitignore`.

One confirmed menu defect (wrong rejected-state slot/transfer admission);
zero duplicate-generation defects demonstrated. Other menu rows are not
claimed proven-safe. No NeoForge tasks or client visual tests were run.
