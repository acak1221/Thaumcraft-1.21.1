## Reproduction

Java 21; private `GRADLE_USER_HOME=$PWD/.gradle-g23` (initial cache copied from the
user's global `.gradle`, no shared build cache writes). Before **each** Gradle command,
`rm -rf fabric/run-gametest/world` was run.

```
./gradlew :fabric:runGameTest --offline --no-daemon --max-workers=2 \
  -PgameTestFilter=g23BossGolemFight,g23BossWardenFight,g23BossPraetorFight,g23BossGiantFight,g23BossTaintacleFight,g23BossPechFight,g23BossPraetorBar,g23BossDeathPlacement
```

Baseline: 8 cases / 4 failed. Failures are actual GameTest assertion failures after
lethal damage, not compilation/source-text tests. Three missing pearl drops share the
stale `eldritch_object` registry ID; the original item metadata 3 is now `primordial_pearl`.
The fourth failure is the praetor's missing inherited boss display contract.

One earlier shell invocation failed before Gradle because `.tmp` did not exist; one
subsequent Gradle invocation compiled but rejected the prefix-only test filter. Neither
is gameplay evidence. The valid baseline used the complete comma-separated test names.

No phase health/cooldown/frenzy state is assigned by the new tests. Stationary positioning,
remote player, no gravity, manually driven native entity ticks and seven-point attributed
damage are declared inputs; these must not be represented as a survival fight or client run.

The first drop-fixed retry passed six of seven selected cases; the golem's undeclared
random champion draw left it alive at the fixture's finite 2400-update limit. This was
not classified as an unkillable-boss defect. The final fixture declares the existing
`ChampionJoinRoll` helper's Bold/ordinary join draws, rather than extending the timeout
or changing gameplay. Additional regressions exercise active golem fire immunity,
warden drown/wither immunity, giant heavy-hit enrage/cap, and headless beam charging.

Pearl fix verification: all **7/7** selected fight/placement-search cases passed
(`.tmp/g23-drop-fixed-declared.log`, `BUILD SUCCESSFUL in 31s`). The separately
reproduced praetor-bar regression remains pending the next fix at this checkpoint.

Praetor bar fix: native server tracking add/remove callbacks, live name/progress updates,
death/discard/unload cleanup. All **8/8** new cases passed (`.tmp/g23-all-fixed.log`,
`BUILD SUCCESSFUL in 43s`), including the previously failing praetor registration check.
The bar test additionally checks viewer departure and live name/progress updates.

A stronger phase-effect probe then failed the warden after the otherwise green eight-case
checkpoint: the actual frenzy ring blocks were metadata **1**, not **11**. Evidence:
`.tmp/g23-field-before.log`, required test failed, `observed=[1]`. Read original warden
197-229 and BlockAiry 384-415 before changing gameplay. Correct resolution uses the native
`airy_hole` hardness group and `FamilyVariant.with(...,11)`; no phase counter changes.

With the field mapping corrected, the same real fight reached its new collision check
and failed there (`.tmp/g23-hazard-before.log`): an actual spawned frenzy field did
not slow or weaken its living victim. This is a separate missing field behavior, not
a reason to weaken the field-identity assertion. Hazard lifecycle verification follows.

The combined collision/expiry probe also failed with actual observations
`collision=false, expired=false` (`.tmp/g23-hazard-expiry-before.log`). A scheduled
tick was registered by the frenzy, but `BlockAiry` had no metadata-11 collision or tick
implementation. The expiry probe invokes the actual native block callback; it does not
advance or claim 250–399 elapsed world ticks.

The extended lifecycle baseline reproduced all three observations together:
`collision=false, scheduledExpired=false, randomTicking=false`
(`.tmp/g23-field-lifecycle-before.log`). Implemented metadata-11 original collision,
scheduled/random retirement and hole-group random-tick eligibility. Native damage/effect
authority stays server-side; horizontal drag is also applied on the client. Other airy
metadata are intentionally outside this boss audit. Original 1% wither probability is
preserved in implementation, not represented as statistically tested.
