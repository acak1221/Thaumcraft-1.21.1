## Diagnosis

The proposed recipe polluter is **not established**. Test-only injection into
the actual native `RecipeManager.replaceRecipes` measured the complete sequence:

```
piston :200 1635 -> 1634
piston :203 1634 -> 1635 (finally)
session :208 1635 -> 1
session :219 1 -> 1635
session :269 1635 -> 1
session :274 1 -> 1635
session :283 1635 -> 1
session :309 1 -> 1635 (finally)
```

The codec body never replaces recipes on this commit. Both actual replacement
bodies are synchronous and restore on Java exception unwinding. A framework
timeout cannot interrupt a synchronous Java method and execute later tests while
its finally remains suspended. No recipe-manager fix is claimed.

Two full runs did not reproduce the quoted infusion failure. Both later crashed
in Bore fixture cleanup. Following that evidence found a genuine **different**
static-state polluter: `regenerationQueueLifecycle` dispatches a real unload on
the shared live test level, permanently inserting it in
`BoreNativeContext.REVOKED_LEVELS`. Later Bore operations correctly refuse that
revoked level. The unload fixture had no restoration at all.

Native negative-control instrumentation measured `before=true afterUnload=false`
and the new lifetime restoration assertion failed (1/1, 25s,
`.tmp/g2c-lifetime-red.log`). The fix scopes the simulated unload with an exact
snapshot of **only this level's** prior revocation marker; native unload must
still be observed revoking it inside the scope. Restore in close, assert live
afterward. No map-wide clear, production authority change or reset API.
See `docs/audit/RECIPE_POLLUTION_FINDINGS.md` for complete evidence and limits.

## Proven sweep fix

Audited 26 singleton-overriding scenarios including the target (25 others), plus
bootstrap probes, event observers, world gamerules/RNG and level-cache clears.
Found and fixed a second issue in that same scenario: the regeneration fixture reset
the complete biome/worldgen configuration to defaults instead of restoring its
caller's exact snapshot. Added a native nondefault-config regression, observed
it fail against the old restore (`.tmp/g2c-config-red.log`, 1/1 required failure,
26s), then changed enqueue to a test-only scoped immutable snapshot restore.
No gameplay code or public API changed. Total: **one other scenario fixed, two
proven singleton-pollution defects**. Other source risks are not mislabeled as
measured failures or fixes.
