## Limits and follow-up

Syntactic coverage is exhaustive for the ledger categories; semantic inspection is not a formal proof of range safety or absence of all duplicates. Numeric/key counts are screened sites, not automatic findings. The main audit records accepted template catalogs, intentional RNG replay differences, constructor/record false positives and quarantine paths that retain data rather than silently lose it.

Behavioral follow-ups require targeted tests and separate changes: side/server-owned cache state; no-throw unavailable maze/biome generation policy; typed diagnostics for unexpected planning failures; schema encapsulation; RNG-sensitive deduplication; class responsibility splits. Four compatibility-only classes remain intentionally untouched pending API policy.
