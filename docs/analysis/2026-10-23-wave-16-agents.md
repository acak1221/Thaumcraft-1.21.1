# Wave of 2026-10-22 — 16 parallel agents, client acceptance, NeoForge parity

## Why this wave exists

The port of TC4 4.2.3.5 to Minecraft 1.21.1 was already deep: 1044 ledger units,
653 `parity_verified`, 315 `partial`, 58 `missing`, 310 required GameTest cases,
1828 JUnit tests, and a NeoForge module that had reached registration parity with
the Fabric bootstrap. Two things blocked the final acceptance:

1. **The client could not be started in the previous sandbox.** `docs/HANDOFF.md`
   recorded "GLX-контекст не создаётся ни с одним драйвером Mesa (100 fbconfig
   есть, контекста нет)" and therefore **no visual acceptance was performed and
   none was claimed**. 24 client units stayed `missing`/`partial` for exactly that
   reason, and the user asked for in-game bug and crash hunting.
2. **315 ledger units were still `partial`** — behaviour that was ported but never
   proven against the 1.7.10 original.

## What changed in this environment

The current machine has a working OpenGL 4.6 context (NVIDIA) on
`DISPLAY=localhost:10.0` (`glxinfo -B` reports a real renderer and 100+ fbconfigs
with a live context). The previous "no GLX context" finding belonged to a
different sandbox and does **not** hold here. The port already ships a complete
client harness (`:fabric:runClientSmoke`, `fabric/src/clientTest/...`, 27.5k
lines) that drives a real integrated world, captures named screenshots and
writes a machine-checked evidence contract, so client acceptance is now
reachable instead of permanently deferred.

Confirmed directly from the 1.21.1 bytecode
(`~/.gradle/caches/fabric-loom/minecraftMaven/.../minecraft-merged-1.21.1-loom*.jar`):
`BaseEntityBlock` overrides `getRenderShape(BlockState)` and returns
`RenderShape.INVISIBLE`, and `PistonBaseBlock` references
`BlockState.hasBlockEntity()`. Every port class that extends `BaseEntityBlock`
without overriding `getRenderShape()` is therefore invisible in the client, and
`hasBlockEntity` being true for the whole block stops the piston. 55 classes in
`common/src/main/java` extend `BaseEntityBlock`; the handoff's open
"cosmetic_solid*/eldritch* invisible" defect is the visible symptom of that
class-wide root cause.

Rules given to every agent: the TC4 original is the only oracle; the
`OpenTC4` 1.7.10 source is the readable comparison target; never modify the
donor jars or `thaumcraft_src/`; **do not run Gradle** (the leader owns the
build; concurrent Loom daemons corrupt the shared cache with
`FileAlreadyExistsException` on `neoforge/21.1.259/minecraft-merged-mojang.jar`);
every finding must cite `file:line` in both the 1.7.10 reference and the 1.21.1
port; a unit may only move to `parity_verified` when the behaviour was actually
fixed; tests are authored by the agent but executed by the leader; claims are
separated into implemented / unit-tested / compile-verified / runtime-verified /
visually verified / unverified.

## Leader-owned work

- All Gradle builds, JUnit runs, GameTest runs and the client runs.
- Integration of the agent branches into `work` (merge, not squash, so every
  agent commit stays individually reviewable).
- The client smoke harness on the real GPU, the visual inspection of the
  produced screenshots, and the crash hunt driven by the real game log.
- NeoForge parity: build, dedicated-server start, and the NeoForge GameTest
  suite that the previous wave left with 22 known failures.

## Status

### Wave 1 — result

All sixteen branches are merged into `work` (94 commits, `be3c816f` -> `4b5f97d6`).

**Scope ledger: 653 -> 841 `parity_verified`; `missing` 58 -> 10; `not_assessed` 18 -> 4.**
The ten remaining `missing` units are the six JEI classes (the original 4.2.3.5 has
no JEI integration at all, and JEI in 1.21.1 is an external mod with its own API
artifact), the four wand pose / beam origin classes that the native wand renderer
replaced, and the two 1.12-only diagnostics. The four `not_assessed` units are the
eldritch FPS diagnostics, the item eldritch renderer (the oracle has none), the
WAILA plugin and the mound template (the oracle has none). Every one of them now
carries a concrete evidence string instead of an open verdict, and the ledger has
**zero** `needs_review` / `unreviewed` units.

**Defects found and fixed in wave 1** (each proven against the byte-exact oracle):
the arcane furnace bonus registry was empty; the advanced node stabiliser never
produced lock two (and lock two never changed the regeneration or the fading
repair roll); the item mirror lost every buffered item on each save; the flux
scrubber never removed the flux gas; the flux goo consumed its RNG rolls without
performing any outcome; the two finite flux blocks had no item at all; the eldritch
trap never warped and used a box instead of the original's sphere; the crab spawner
used the wrong sound and never produced a vent; **the Outer Lands boss rooms were
never generated at all**; the crimson portal compared a squared distance against a
linear one; the cullable-aspect loop hung the server; `getStackInRowAndColumn`
returned the transposed cell; `areItemsEqual` lost the damage rule; the hotbar wand
query was inverted and scanned 36 slots; the vision cone was anchored at the wrong
height; the bell's marker selection deleted a coloured marker; the alchemy golem
never found an alembic above a gap; the fire bat spawned in daylight; the taint
swarm and the taintacle could not spawn in daylight; the tainted animals had no
armour; the magical leaves lost the original decay flag; the custom plant item
placed itself on any block; **five GUI screens drew their sheets as solid black**
(`GuiGraphics.blit` does not enable blending); the levitator's glow was tinted
green instead of `#DD11FF` and drawn on the wrong side of the block; three TC4 keys
were bound to F/G/H although the original binds none; the research note did not
cost a paper; the thaumometer had no scan sound; ten recipes had the wrong
ingredient; the death aspect orbs are still open (wave 2).

**The ledger was also corrected where earlier waves were wrong**: six rows that
were marked `parity_verified` were not, and the previous audit's reading of the
oracle's `MazeGenerator` (which differs between the 4.2.3.5 jar and the OpenTC4
tree) turned out to be a false positive in the port's favour.

**Oracle.** The private oracle was reconstructed here from the repository's own
`Thaumcraft-1.7.10-4.2.3.5.jar` with CFR 0.152 (default options): **859 of 859
files match the fingerprints and line counts the ledger already records**, so
`scripts/porting/extract_tc4_definitions.py --check` and
`scripts/porting/update_scope_ledger.py --check` now really run
(`stale_review_fingerprints: 0`, `research_count: 201`,
`research_key_category_sha256 397d6208…`, `text_page_sha256 66a10cd3…`).
`/home/cyberfox-kali/OpenTC4` is a second opinion only: it differs from the jar
in real places (the labyrinth's boss-room corner, the vent colour).

**Verification on this machine (real output, not inherited):**
`:common:compileJava` green; `:common:test` 2013 tests with the 14 failures of
wave 1 listed in `docs/analysis/2026-10-23-agent-testsuite.md`; `:fabric:runGameTest`
318 scenarios, 0 failures; `:fabric:build` green; a dedicated server reaches
"Done (15.319s)!" with no error in the log.

**The client now runs.** The previous handoff recorded "GLX-контекст не создаётся
ни с одним драйвером Mesa" and therefore no visual acceptance at all. That was a
property of the earlier sandbox. This machine has a real OpenGL 4.6 context on
`DISPLAY=:0` (Intel UHD, direct rendering); the session's original
`localhost:10.0` was a TCP X server that is no longer listening, which is why the
first attempt failed with GLFW "Failed to detect any supported platform", and the
sddm-protected X authority is extracted once into a private `XAUTHORITY`. The
client starts, renders real frames and plays; the remaining blocker for the full
client smoke is the experimental-world confirmation dialog of a world that was
copied out of a GameTest run.

**Additional leader-side check.** A static verifier for the production mixins
(`.tmp/leader/check_mixin_targets.py`) resolves every `@At` target of the 33
authored production mixins against the real remapped 1.21.1 classes: **all 33
resolve**, so no mixin is silently inert. The only two unresolved targets are
`BlockState.onDestroyedByPlayer` and `BlockState.canHarvestBlock`, which are
NeoForge-patched methods and are checked against the NeoForge jar instead.
