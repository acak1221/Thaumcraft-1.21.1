# Интеграции 1.21.1: EMI, Mod Menu, экран настроек и переводы тегов — 25.10.2026

Базис: `bebe0a7` (ветка `fabric`). Цель волны — адаптировать порт к экосистеме Minecraft 1.21.1
там, где у TC4 1.7.10 не было собственного аналога, и исправить дефекты, найденные при запуске
настоящего клиента. Игровые значения, исследования, рецепты и аспекты TC4 не менялись.

## Что сделано

### 1. Необязательная интеграция с EMI

В TC4 4.2.3.5 рецепты читались только в Таумономиконе (NEI-плагин был отдельным аддоном).
Теперь, если установлен [EMI](https://modrinth.com/mod/emi), порт показывает свои рецепты:

| Категория EMI | Источник | Станция |
|---|---|---|
| Магический верстак | `thaumcraft:arcane` — shaped/shapeless, а также все сочетания стержень × колпачок, которые принимает сам зарегистрированный рецепт жезла/посоха и скипетра (стоимость берётся у рецепта для этого сочетания) | Магический верстак |
| Тигель | `thaumcraft:crucible` и рецепты аддонов через `ProgrammaticRecipes.crucibles` | Тигель |
| Магическая инфузия | `thaumcraft:infusion_stack` и рунное усиление (робы с закалкой 0–4, как страница книги) | Матрица инфузии |
| Зачарование инфузией | `thaumcraft:infusion_enchantment`: все предметы, к которым применимо зачарование, I уровень, опыт и эссенция | Матрица инфузии |
| Сочетание аспектов | Два компонента → составной аспект | Стол исследований |

Подробности:

- **Аспекты — полноценные стеки EMI** (`AspectEmiStack`): иконка, окрашенная цветом аспекта, как
  на страницах книги; подсказка: латинское имя, перевод, «первичный»/«составлен из», количество.
  Все 48 аспектов есть в индексе EMI, «использования» аспекта находят все рецепты тигля, инфузии и
  верстака, где он нужен. Аспекты подключены как *катализаторы*: EMI индексирует по ним
  «использования», но фильтр «можно скрафтить» и автозаполнение смотрят только на предметы
  (проверено по байткоду EMI 1.1.22: `EmiPlayerInventory.canCraft` читает только `getInputs`,
  `EmiRecipes$Manager` строит byInput и по входам, и по катализаторам).
- **Строка исследования**: маленький Таумономикон и название исследования; зелёная, если игрок
  его знает, красная — если нет; подсказка «Исследование: …/Ещё не изучено». Знание берётся из
  синхронизированного `KnowledgeAccess` клиента.
- **Автозаполнение магического верстака**: кнопка «+» EMI раскладывает предметы по сетке
  3×3 (`ArcaneWorkbenchRecipeHandler`, слоты меню 2–10). Это обычные клики по слотам: вис
  жезла и проверка исследования по-прежнему выполняются сервером при взятии результата.
- **Жезлы различаются в EMI** по стержню, колпачкам и признаку скипетра. Без этого R на любом
  жезле показывал все 179 вариантов; теперь — рецепт именно этого жезла, а полный список
  доступен через «использования» стержня/колпачка и через категорию верстака.
- Один сломанный датапак- или аддон-рецепт не скрывает остальные: преобразование каждого
  рецепта обёрнуто и пишет предупреждение в лог `Thaumcraft/EMI`.
- Зависимость только `modCompileOnly "dev.emi:emi-fabric:…:api"`; плагин лежит в модуле Fabric
  (`thaumcraft.fabric.compat.emi`) и загружается только EMI через точку входа `emi`. Без EMI мод
  работает как раньше; в JAR EMI не входит. `-PwithEmi` добавляет EMI в `runClient` для ручной
  проверки, GameTest и обычные запуски идут без него.
- **Почему не в `common`.** Первая версия лежала в `common` с xplat-API. Сборка и клиент с EMI
  работали, но GameTest без EMI упал до старта: dev-трансформер Architectury вычисляет фреймы
  common-классов и загружает упомянутые типы (`NoClassDefFoundError: dev/emi/emi/api/stack/EmiStack`).
  Положить API-jar в dev-classpath нельзя: все API-jar EMI для Fabric содержат `fabric.mod.json`,
  и загрузчик принимает их за мод EMI без реализации (`ClassNotFoundException: EmiMixinPlugin`).
  Классы модуля Fabric трансформером не обрабатываются, поэтому плагин перенесён туда. Для
  NeoForge потребуется своя точка входа (`@EmiEntrypoint`), когда работа над ним возобновится.

### 2. Mod Menu и метаданные Fabric

- Точка входа `modmenu`: кнопка настройки открывает экран настроек мода (аналог кнопки Config
  из списка модов Forge 1.7.10, `ThaumcraftGuiFactory`).
- `fabric.mod.json`: иконка (текстура Таумономикона из оригинала, копируется в ресурсы Fabric
  при сборке, как access widener), ссылки homepage/sources/issues, точное описание,
  `suggests` для EMI и Mod Menu.
- Найдено в клиенте: в dev-запуске Mod Menu не видел иконку, потому что ресурсы `common` не
  входят в корень Fabric-мода (`NoSuchFileException …/fabric/build/resources/main/…`). Копия в
  ресурсы Fabric исправляет это в обоих режимах.

### 3. Экран настроек переписан на виджеты 1.21.1

**Дефект (виден на кадре `images/2026-10-25-config-before.png`):** при стандартном окне
854×480 (GUI ×2) строки настроек выходили за панель и налезали на «Done», названия вкладок
обрезались («Monster_», «ieneration»), заголовок категории наползал на вкладки, прокрутки не было.

Теперь: вкладки с понятными названиями (подсказка — исходное имя категории), прокручиваемый
список `ContainerObjectSelectionList`, переключатели ВКЛ/ВЫКЛ (`CycleButton`), ползунки для
чисел (`AbstractSliderButton`; сложность исследований показывает «Лёгкая/Обычная/Сложная»),
для каждой настройки — название и подсказка с объяснением и исходным ключом файла. Формат файла
`config/thaumcraft.properties`, ключи, категории и значения по умолчанию не изменились
(`ThaumcraftConfigStore` не трогался, его тесты продолжают проходить).

### 4. Переводы тегов

Fabric (`TranslationConventionLogWarnings`) и EMI предупреждали о 45+ непереведённых тегах
предметов. Добавлены `tag.item.thaumcraft.original_ore.*` (аналоги словаря руд 1.7.10),
`tag.block.c.ores.*` для руд Thaumcraft и `tag.block.thaumcraft.taint` (en/ru, 2677 ключей в
каждом языке, паритет сохранён). После исправления оба предупреждения в логе клиента исчезли.

### 5. Шум `No data fixer registered`

При каждом запуске (клиент, сервер, GameTest) ванильный `EntityType.Builder.build(String)`
писал 55 строк `ERROR No data fixer registered for thaumcraft:<сущность>`: он спрашивает у схемы
data-fixer тип строящейся сущности и сразу отбрасывает ответ (видно по байткоду: `invokestatic
Util.fetchChoiceType` → `pop`). `EntityTypeSchemaNoticeMixin` пропускает этот запрос только для
ключей `thaumcraft:`; тип сущности, её сохранение и сущности других модов не меняются.

### 6. Нестабильный GameTest

Базовый прогон на `bebe0a7` в этом окружении дал **466/467**: упал
`shockFocusPaysTargetsAndRespectsCooldown` с сообщением «native armor/toughness reduces the
four-point hit instead of being bypassed». Причина — фикстура: бронированный зомби добавлялся
через `addFreshEntity`, и случайный бросок чемпиона TC4 (оригинальный `entitySpawns`) мог
сделать его «Warded» чемпионом, чей щит поглощает удар. В проекте уже есть детерминированный
помощник `ChampionJoinRoll.join` для таких фикстур; `ShockFocusRuntimeChecks` теперь его
использует. Производственный код не менялся.

### 7. Проверка ресурсов

`composed_resources` отклонял базис: `ThaumcraftGearModelsClient.java` изменён в `bebe0a7`
без пересмотра контракта. Изменение перенесло только цепочку матриц позы в `WandUsePose.apply`;
поставщики `ResourceLocation` не изменились — отпечаток обновлён с этой пометкой. Новые
динамические `ResourceLocation` EMI (ID категорий, синтетические ID рецептов, ID стеков
аспектов) — не пути к файлам; внесены в инвентарь `dynamic_factories` согласно политике контракта.
