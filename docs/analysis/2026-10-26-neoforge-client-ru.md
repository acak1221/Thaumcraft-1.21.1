# Настоящий клиент NeoForge: два дефекта, ломавших любой клиент, и EMI на NeoForge — 26.10.2026

Базис: `72cf7ee` (ветка `fabric`). После того как набор GameTest NeoForge стал зелёным
([отчёт](2026-10-26-neoforge-gametest-parity-ru.md)), порт впервые запущен в настоящем клиенте
NeoForge 21.1.259 под Xvfb (окно 854×480, GUI ×2, программный рендер Mesa llvmpipe, без звука).
GameTest работает на выделенном сервере и клиентский код не загружает, поэтому оба дефекта ниже
он поймать не мог.

## Дефект 1: клиент падал при входе в мир (mixin оверлея порчи)

Падение при входе в любой мир: `MixinTransformerError` →
`Critical injection failure: … TaintOverlayChunkLayerMixin … (0/1) succeeded. Scanned 0 target(s)`.

NeoForge оставляет ванильную сигнатуру `SectionCompiler.compile(SectionPos, RenderChunkRegion,
VertexSorting, SectionBufferBuilderPack)` только как делегат к перегрузке с лишним списком
`AdditionalSectionRenderer`. Цикл по блокам с `PoseStack.popPose()` есть только в перегрузке
(проверено по байткоду патченного класса). Селектор `method="compile"` без дескриптора выбирает
первый подходящий метод, то есть делегат. Точки внедрения там нет, а `defaultRequire: 1` делает
это фатальным.

Исправление: `method="compile*"` выбирает оба метода; внедрение попадает в тот, где есть
`popPose`. На Fabric метод один, поведение не меняется.

**Проверка остальных mixin.** Во временном диагностическом запуске (из кода убран) на титульном
экране вызывался `MixinEnvironment.audit()`. Он принудительно загрузил 13 ещё не загруженных
классов-целей, в том числе `SectionCompiler`, без единой ошибки. Остальные цели к этому моменту
уже загрузились при старте. При `defaultRequire: 1` любая ошибка была бы фатальной, поэтому все
mixin порта на клиенте NeoForge применяются. Единственное предупреждение — необязательный mixin
самого EMI для JEI.

## Дефект 2: на NeoForge терялись GUI, модели снаряжения и рендереры сущностей

После первого исправления мир загрузился, но клиент упал через пару минут:
`NullPointerException … EntityRenderer.shouldRender` — у сущности Thaumcraft не было рендерера.

`ClientSetup.init()` на NeoForge вызывался из `FMLClientSetupEvent`. Но NeoForge 21.1 рассылает
`RegisterMenuScreensEvent`, `EntityRenderersEvent.RegisterLayerDefinitions` и
`EntityRenderersEvent.RegisterRenderers` из `ClientHooks.initClientHooks` в конструкторе
`Minecraft`, задолго до настройки клиента. Реестры Architectury для экранов меню, слоёв моделей
и рендереров сущностей применяют регистрации только внутри этих событий (проверено по байткоду
`MenuRegistryImpl`, `EntityModelLayerRegistryImpl`, `EntityRendererRegistryImpl` 13.0.11). Поэтому
на NeoForge терялись:

- все 17 экранов Thaumcraft — ни один GUI не открылся бы;
- все 8 слоёв моделей снаряжения (робы, крепостная, рыцарская и командирская броня);
- рендереры всех сущностей Thaumcraft — первая же отрисованная сущность роняла клиент.

Цвета блоков и предметов, привязки клавиш и свойства предметов не пострадали: у этих реестров
Architectury есть запасной путь для поздней регистрации.

Исправление: `ClientSetup.init()` вызывается первым делом в обработчике
`RegisterClientExtensionsEvent` — это первое событие, которое рассылает `initClientHooks`.
Реестры к этому моменту заполнены: тот же обработчик и раньше брал предметы через `.get()`.
Fabric не затронут. `NeoForgeLoaderParityTest.theSharedClientSetupRunsBeforeTheClientHookEvents`
не даёт вернуть вызов в `FMLClientSetupEvent`.

## EMI на NeoForge

Плагин перенесён из модуля Fabric в общий исходный каталог `compat/emi/src/main/java`
(пакет `thaumcraft.compat.emi`). Его компилируют оба модуля загрузчиков, но не `common`: туда
плагин класть нельзя из-за dev-трансформера Architectury (см. отчёт от 25.10). Fabric находит
плагин через точку входа `emi` в `fabric.mod.json`, NeoForge — через аннотацию `@EmiEntrypoint`.
NeoForge компилируется только с API EMI (`emi-neoforge:…:api`), в `neoforge.mods.toml` EMI указан
как необязательная клиентская зависимость. `-PwithEmi` подключает EMI к `runClient` и на NeoForge.
Проверка ресурсов (`composed_resources`) теперь сканирует и `compat/emi`, иначе динамические ID
EMI выпали бы из инвентаря молча.

## Нестабильная фикстура

Один полный прогон NeoForge дал 451/452: `relics_and_reliquaries_keep_their_original_rules`
не нашёл ни одного волокна порчи после бутыли. Оригинал пропускает столбцы, которые уже стали
биомом порчи, а GameTest строится там, куда его поставит прогон, иногда в естественном биоме
порчи. Тогда волокон нет по правилу оригинала, и это не дефект мода. Фикстура теперь ставит
столбцам дорожки равнины на время взрыва и возвращает их биом после. Сценарий проходит на обоих
загрузчиках отдельно и в полных прогонах.

## Не проверено

- Мультиплеер NeoForge (выделенный сервер и клиент), выживание.
- Все 17 экранов по отдельности на NeoForge: открыт только магический верстак.
- Рендер оверлея волокон порчи рядом с другими блоками на обоих загрузчиках.
