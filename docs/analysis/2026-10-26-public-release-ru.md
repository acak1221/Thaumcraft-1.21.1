# 26.10.2026 — Публикация репозитория: что проверить до открытия

Владелец попросил сделать страницу GitHub красивой, чтобы «отдать в публику». Страница
переписана (`README.md`, `README.ru.md`, кадры в `docs/images/readme`). Видимость репозитория,
ветку по умолчанию и историю git меняет только владелец; ниже — что в репозитории сейчас мешает
или требует решения. Это не юридическая консультация.

## 1. Оригинальные JAR в репозитории

В корне отслеживаются два файла, которые являются дистрибутивами чужих модов:

| Файл | Размер | Что это |
|---|---|---|
| `Thaumcraft-1.7.10-4.2.3.5.jar` | 12,6 МБ | оригинальный Thaumcraft 4.2.3.5 (Azanor) — эталон поведения |
| `Thaumcraft-1.12.2-6.1.BETA26.jar` | 11,4 МБ | Thaumcraft 6.1 beta 26 (Azanor) |

Открытие репозитория сделает их общедоступными для скачивания — это распространение мода
Azanor, на которое разрешения нет. Удаления из текущего дерева недостаточно: файлы остаются в
истории (`git count-objects`: 101 МБ упакованной истории) и скачиваются клоном. Нужна перезапись
истории (например, `git filter-repo --path Thaumcraft-1.7.10-4.2.3.5.jar --path
Thaumcraft-1.12.2-6.1.BETA26.jar --invert-paths`) и принудительный push всех веток и тегов — это
необратимо для всех клонов, поэтому решение владельца.

Скрипты `scripts/porting/extract_config_aspects.py` и `convert_warp_shaders.py` читают JAR из
корня. После удаления JAR должен лежать локально (в `.gitignore`), а скрипты продолжат работать
у того, у кого он есть.

## 2. Извлечённые ресурсы оригинала

`thaumcraft_src/` (1096 файлов: 821 png, 111 ogg, языки, модели) — ресурсы из оригинального JAR.
Те же текстуры и звуки входят в сам мод (`common/src/main/resources/assets/thaumcraft`), иначе он
не выглядит как Thaumcraft. Это общее положение всех портов TC4: права на ресурсы у Azanor, и
`THIRD_PARTY_NOTICES.md` прямо говорит, что права на публикацию не установлены. Решение
«публиковать порт с оригинальными ресурсами» — риск владельца репозитория.

## 3. Наследие 1.12

`src/` (3140 файлов) — код и ресурсы порта 1.12.2 «Thaumcraft-4.2-FOREVA», от которого вырос
проект; в сборку 1.21.1 не входит. Его лицензия выводится из того же репозитория (MIT-шаблон, не
разрешение Azanor). Можно оставить как историческую справку или убрать вместе с JAR.

## 4. Утверждения в репозитории, которые надо привести в соответствие

- `AGENTS.md`: «No public push/release is authorized by the local port request».
- `THIRD_PARTY_NOTICES.md`: «The new migration does not publish a repository, push source, or
  release a JAR externally. Publication rights have not been established by this task.»

Если владелец решит открыть репозиторий, эти строки стоит заменить на его решение, иначе
страница противоречит сама себе.

## 5. Ветка по умолчанию

Ветка по умолчанию на GitHub — `main`, вся работа идёт в `fabric`. Посетитель видит README из
`main`, то есть старый. Нужно влить `fabric` в `main` (pull request) или сделать `fabric` веткой
по умолчанию.

## 6. CI

Все запуски «Build and test Fabric 1.21.1» с 23.10.2026 (последние 30 в списке) завершаются
неудачей за 3–4 секунды, а их журналы недоступны (HTTP 404). Так выглядит задание, которое
GitHub не запустил, — обычно исчерпаны бесплатные минуты Actions приватного репозитория или
проблема с оплатой; код здесь ни при чём (локально сборка и тесты проходят). У публичного
репозитория стандартные раннеры бесплатны, но это нужно проверить во вкладке Actions. Поэтому в
README нет значка CI.

## 7. Выпуски

`v0.1.0-alpha.2…5` опубликованы под старым именем «Thaumcraft 4.2 FOREVA», `v0.1.0-alpha.6` —
черновик. После решения по пунктам 1–4 стоит выпустить новую альфу под именем «Thaumcraft 4
Reload» с jar для Fabric и NeoForge, на который ссылается README.
