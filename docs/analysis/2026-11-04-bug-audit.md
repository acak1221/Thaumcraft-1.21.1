## Independent adjacent chests

`InventoryUtils.getDoubleChest` used native `ChestBlock.getConnectedDirection`
without checking `ChestType.SINGLE`. The helper returns a direction for a single
chest too. Consequently the public insertion helper could send overflow into an
independent adjacent chest. Built-in atomic machine adapters already had their
own pair checks; this fix repairs the public compatibility helper.

The resolver now requires current, loaded block entities, identical chest blocks,
opposite halves and equal facing. Oracle `InventoryUtils.java:458–473` reads the
actual cached adjacent halves, so this repairs the native adaptation without
changing TC4's intended behavior.

Native regression `inventoryInsertionOnlyUsesTheActualDoubleChestPartner`
covers independent single chests, normal/trapped mismatch, incompatible halves
and facing, both directions of a genuine pair, simulation, returned overflow and
exactly one committed insertion. Fixture inventories are cleared before their
original blocks are restored.

## Flux scrubber extraction

Both public extraction overloads subtracted `Math.min(stock, request)` without
checking its sign. With zero stock, a request of `-4` returned `-4` and created
four essentia; `Integer.MIN_VALUE` could also overflow the stored counter.
Both routes now return zero without mutation for a nonpositive request, while
positive requests retain the original type/face behavior and bounded debit.

Oracle `TileFluxScrubber.java:183–187` contains the same negative extraction bug.
This is an intentional resource-conservation correction. The native test checks
both routes at zero and positive stock, zero/negative/minimum-integer requests,
unchanged complete saved NBT, and a maximum-integer positive request.

## Flux scrubber charge persistence

The scrubber spent four charges on every conversion attempt but called
`setChanged` only on the one-in-four successful outcome. If the chunk was clean,
the failed debit could be lost when it unloaded. The debit now marks the chunk
dirty on both outcomes. The four-charge price and random distribution are intact.

Oracle `TileFluxScrubber.java:48–56` has the same persistence defect. The existing
native test now injects a failed conversion roll, clears the owned chunk's dirty
flag, and checks the debit, dirty flag and saved NBT. The exact world RNG is
restored synchronously in `finally`.

## Retained JEI source pages

An already open source page held materialized item/aspect slots after a knowledge
reset. The provider correctly stopped returning new pages, but the retained GUI
and JEI history still exposed the old ingredients. Source pages now check their
original connection and the current scan before returning the item; a JEI
`ISlottedRecipeWidget` applies the same guard to drawing and native slot hit tests.
This closes stale tooltip/click targets as well as stale rendering. A new world
cannot reactivate the old page even after independently scanning the same item.

The actual JEI client probe keeps its GUI open while the server resets knowledge,
retains a real `IRecipeLayoutDrawable`, and checks its item/aspect hit tests before
and after the reset. It also rebuilds history while scans are revoked, then
checks that a same-connection rescan restores both original and rebuilt layouts.
It then scans clay in a second fresh world and checks that the first-world pages
stay retired. Fixtures explicitly supply scans; this is not survival acquisition
or multiplayer acceptance.
