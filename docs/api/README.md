# Addon contracts — Minecraft 1.21.1

1. **Keep units at the call boundary.** `AspectList` does not convert units. Arcane recipe costs are whole vis; focus costs and native wand capacities are **centivis** (100 = one vis). Crucible/infusion costs are essentia/aspect units, not centivis or millibuckets. Gear discounts use percentage points; cap modifiers are multipliers. World positions/ranges use blocks, squared distances use blocks², and use/cooldown timers use game ticks. Read the individual declaration before moving an amount between APIs.
2. **There is no package-wide null or ownership policy.** Some registrations ignore null, some reject it, and some throw `NullPointerException`. Some getters return null, some return an empty list, and many return live mutable references. Follow the member's Javadoc; an undocumented interface is not permission to assume defensive copies or null tolerance. `AspectList.copy()` copies the map, not the mutable `Aspect` identities.
3. **World mutations belong to the owning server thread.** Do not call payment, graph mutation or world-scoped recipe registration from render/network-worker callbacks. Complex object-tag registration requires a loaded server recipe context. Global registration lists are not concurrent addon registries; coordinate initialization with the host. Client rendering/translation queries are not authority to change server state. An interface callback alone does not establish a universal side/thread guarantee.
4. **Retained shape does not mean working gameplay integration.** Numeric enchantment IDs, subtype metadata, global furnace lookup and arbitrary NBT patches are not native 1.21.1 identities. Follow `@deprecated` replacement guidance; signatures remain available, without a removal date or a binary/source-compatibility promise for 1.7.10 addons. TC6 theorycraft/stages and the generic scannable registry are not wired into TC4 gameplay; native foci use `ItemFocusBasic`, not `IWandFocus`.
