# Перенос рецептов (alpha.14)

Thaumcraft управляет расстановкой ингредиентов. Кнопка `+` в Таумономиконе и необязательный
обработчик верстака EMI отправляют только идентификатор рецепта, ID текущего меню и признак
максимального заполнения. Сервер находит рецепт и перемещает существующие ингредиенты;
он не принимает стеки от клиента, не создаёт результат и не расходует вис жезла при расстановке.

Магический верстак поддерживает ванильные рецепты shaped/shapeless, фиксированные native/API
магические рецепты и канонические варианты жезлов/скипетров, показанные в EMI. Shift запрашивает
столько полных наборов, сколько помещается. Источниками служат только основной инвентарь
игрока, панель быстрого доступа и девять ячеек матрицы; жезл, броня и вторая рука исключены.
Прежнее содержимое матрицы возвращается в инвентарь. Если не хватает ингредиентов, исследования
или места для возврата, оба инвентаря остаются без изменений.

При переносе из отдельно открытой книги сервер открывает ближайший доступный магический верстак.
Если совместимое меню уже открыто, перенос использует его. Аддон для хранения не требуется;
рецепты тигля, наполнения и других машин не являются заполнением верстака.

## Меню аддонов

Реализуйте `thaumcraft.api.crafting.transfer.RecipeTransferTarget` в фактически открытом
`AbstractContainerMenu`:

1. `recipeTransferContents()` предоставляет ячейки матрицы 0–8.
2. `canTransferRecipe(actor)` проверяет текущего игрока/сессию, действующий блок, расстояние
   и разрешения внешнего хранилища. Перед фиксацией проверка выполняется повторно.
3. `recipeTransferSourceSnapshot(actor)` возвращает упорядоченные копии ячеек-источников;
   по умолчанию это 36 ячеек основного инвентаря и панели быстрого доступа игрока.
   Для внешних источников метод можно переопределить.
4. `applyRecipeTransfer(actor, plan)` сравнивает все ожидаемые ячейки матрицы/источников,
   затем атомарно заменяет их запланированными значениями до отправки уведомлений.

`RecipeTransferPlan` копирует списки стеков при создании и при доступе. Возвращайте false
без изменений, если ожидаемое состояние или разрешения устарели. После фиксации возвращайте
true, даже если последующее уведомление завершилось ошибкой или закрыло меню. Симуляции
извлечения недостаточно: адаптер внешнего хранилища сам должен гарантировать оплату,
сохранность ингредиентов и атомарную фиксацию.

Клиентские обработчики могут вызвать `RecipeTransferNetworking.request(recipeId, maximum)`
при открытом совместимом меню. Общий серверный движок не зависит от Refined Storage.
Перед фиксацией он повторно проверяет исследование и фактический предикат рецепта.
Пользовательским классам динамических рецептов нужен явно поддерживаемый шаблон;
рецепт только для отображения не разрешает перенос.
